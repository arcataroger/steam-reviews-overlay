# Steam card inventory

The inventory is a deterministic crawl of every page reachable from the store's top menu. For each
page it finds every game-card candidate (any `/app/N`, `/news/app/N` or `data-ds-appid` link, walked
up to the largest single-game ancestor the same way `src/content.ts` does), reduces it to a
structural signature, and records example markup, computed styles and what the extension did with it
(claimed element, highlight shape, badge placement). Kinds are deduped across pages into a master set
with a coverage verdict per kind.

Files:
- `docs/inventory/nav-urls.json` — the menu URL list (regenerated by step 1).
- `docs/inventory/pages/<slug>.json` — per-page raw inventory (regenerated by step 2).
- `docs/inventory/master.json` / `master.md` — the master set (regenerated by step 3).
- `docs/inventory/kind-names.json` — curated human names, keyed by master key. Hand-maintained.
- `docs/inventory/README.md` — the coverage map: what the extension does per kind and known gaps.

## Procedure

1. Enumerate the menu: `npm run inventory:nav` (hovers each top tab on a fresh load; ~1 min).
   Compare with git diff: new menu entries mean new pages to cover.
2. Crawl: `npm run build && npm run inventory:crawl` (~45 min for ~100 pages; uses dist/chrome).
   To crawl a subset: `node scripts/inventory.mjs docs/inventory/pages <url> [url...]`.
   Reads-only. Sign-in walls and age gates come back as 0 cards and are listed in the page table.
3. Merge and diff: `npm run inventory:merge` writes the new master set;
   `git diff --stat docs/inventory` plus `node scripts/inventory-diff.mjs <(git show HEAD:docs/inventory/master.json) docs/inventory/master.json`
   lists kinds that appeared, disappeared, changed hashed classes, or lost coverage.
4. Name anything new: `master.md` flags unnamed kinds; look at the example with
   `node scripts/inventory-summary.mjs docs/inventory/pages --example <slug> <kindIndex>` and add
   `"<master key>": "<display name>"` to `kind-names.json`, then re-run step 3.
5. Act on coverage: a kind marked `gap` (never claimed) or `partial` (some cards unclaimed, claimed
   on a different element, or left without a label although Steam shows no summary) needs a fix in
   `src/content.ts` (card walker, never-a-card list, placement candidates) or a deliberate entry in
   the "Known gaps" section of `docs/inventory/README.md`. After fixing, rebuild and re-run step 2 on
   the affected pages, then step 3.
6. Run the visual harness on the pages of any changed kind
   (`node scripts/visual-pass.mjs <outdir> <url...>`) and commit `docs/inventory`.

## Reading a kind

- Master key `a.search_result_row` = tag + stable classes. `div.+2h|.carousel__slider|news,art,carousel`
  = a React element with 2 hashed classes, under that section, holding art in a carousel with a
  news link. Hashed classes (`_3r4Ny9tQdQZc50XDM5B2q2`) change when Steam rebuilds; the key does not.
- `ours`: `same` = the extension claimed exactly this element; `other:<sig>` = it claimed an
  ancestor/descendant instead (check whether the highlight then outlines the wrong box);
  `unclaimed` = no treatment at all. `badge=none` is expected when Steam already prints its summary
  and local/global agree, or the card is narrower than 120px.
